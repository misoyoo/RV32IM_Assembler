# AI 사용 및 프롬프트 기록

## 1. AI 사용 여부와 사용 범위

이 프로젝트는 구현과 디버깅 과정에서 생성형 AI를 사용했다. AI는 설계 설명, C 코드 초안 및 수정, 오류 원인 분석, 테스트 케이스 제안, 구현 결과 검토에 활용했다. 최종 코드를 프로젝트에 반영하고 컴파일·실행 결과를 확인하는 과정은 사용자가 직접 수행했다.

## 2. 초기 구현 요청 프롬프트 정리

아래는 프로젝트 초기 요구와 대화에서 반복적으로 사용한 핵심 요청을 과제 제출용으로 정리한 프롬프트다. 전체 대화의 모든 입력을 축어적으로 옮긴 기록은 아니며, 핵심 요구를 요약·재구성한 것이다.

> C 언어로 RISC-V RV32IM 어셈블러를 구현하려고 한다. 먼저 전체 구조를 설계하고, Parser, Register, Encoder, Symbol Table, Pass 1, Pass 2를 분리해 구현해줘. 코드는 기존 파일 구조와 함수 인터페이스를 최대한 유지하고, 각 단계의 역할과 데이터 흐름을 설명해줘. R/I/S/B/U/J 형식과 CSR 및 System 명령어 인코딩을 지원하도록 해줘.

> 어셈블리 소스의 라벨, mnemonic, operand를 파싱하고, `.text`, `.data`, `.bss`, `.equ`, `.global` 및 데이터 지시어를 처리하는 방향으로 구현해줘. 심볼 주소와 섹션 크기를 Pass 1에서 계산하고 Pass 2에서 실제 기계어와 데이터를 출력하도록 해줘.

## 3. 검증 및 디버깅 프롬프트 정리

> 현재 구현한 코드와 실행 로그를 기준으로 오류 원인을 찾아줘. 기존에 정상 동작하는 코드를 불필요하게 전면 교체하지 말고, 실제 코드 위치와 수정할 부분을 구체적으로 설명해줘.

> 제공된 어셈블리 예제를 원본 그대로 사용해서 Pass 1과 Pass 2가 모두 성공하는지 확인할 수 있도록 테스트 절차와 명령어를 제시해줘. 예제 파일은 테스트를 위해 수정하지 말아줘.

> 잘못된 mnemonic, 중복 라벨, 정의되지 않은 심볼, 잘못된 레지스터, 즉시값 범위 초과, 지원하지 않는 BSS 지시어를 입력했을 때 올바르게 실패하는지 검증해줘. 실패 시 출력 파일이 잘못 생성되지 않는지도 확인할 수 있게 해줘.

> `.bin`의 실제 크기와 Pass 1에서 계산한 예상 크기를 비교하고, listing 파일에 주소·기계어·원본 소스 줄·심볼 테이블이 올바르게 기록되는지 확인할 수 있도록 해줘.

## 4. 실제 검증 방식

AI가 제시한 코드나 수정 사항을 그대로 성공으로 간주하지 않고, 프로젝트에서 직접 빌드와 실행을 수행했다. 구체적인 빌드 명령, 제공 예제 전체 실행, BSS 배치 테스트, 오류 입력 테스트와 관찰 결과는 [검증 과정 및 결과](RESULTS.md)에 정리했다.

## 5. 제출 시 유의 사항

이 문서의 프롬프트는 실제 대화에서 사용한 모든 문장을 그대로 수집한 전문이 아니라 핵심 요청을 제출용으로 요약·재구성한 것이다. 교수자가 실제 대화 원문을 요구하는 경우에는 ChatGPT 대화 기록에서 최초 구현 요청과 주요 검증 요청을 확인해 별도로 첨부한다.

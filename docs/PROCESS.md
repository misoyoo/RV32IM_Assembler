# 구현 과정 및 동작 상세

## 1. 프로젝트 개요

이 프로그램은 RV32IM 어셈블리 소스를 읽어 명령어와 데이터의 메모리 배치를 계산한 뒤, 기계어를 raw binary(`.bin`)로 출력하는 C 기반 2-pass 어셈블러다. 별도의 링커나 ELF 생성기는 포함하지 않는다.

전체 흐름은 다음과 같다.

1. 명령행 인자로 입력 어셈블리 파일, 출력 바이너리 파일, listing 파일 경로를 받는다.
2. Pass 1에서 섹션 크기와 심볼 주소를 계산한다.
3. Pass 2에서 명령어를 인코딩하고 초기화 데이터를 기록한다.
4. 바이너리 크기를 예상 크기와 비교하고 listing 및 binary 파일을 출력한다.
5. 사용한 메모리와 파일 자원을 정리한다.

## 2. 소스 파일별 역할

| 파일 | 역할 |
|---|---|
| `main.c` | 명령행 인자 처리, 파일 열기, Pass 1·2 호출, 결과 크기 검증, 출력 및 정리 |
| `parser.c`, `parser.h` | 한 줄의 라벨, mnemonic, operand를 파싱 |
| `register.c`, `register.h` | 레지스터 이름을 번호로 변환 |
| `encoder.c`, `encoder.h` | 명령어 형식별 기계어 인코딩 |
| `directives.c`, `directives.h` | 지시어 크기 계산, 표현식 평가, `.equ` 및 문자열 처리 |
| `symbol_table.c`, `symbol_table.h` | 심볼의 이름, 주소, 유형, 전역 여부 및 정의 여부 관리 |
| `pass1.c`, `pass1.h` | 섹션 크기 계산, 메모리 배치, 심볼 등록 |
| `pass2.c`, `pass2.h` | 기계어 및 데이터 출력, listing 항목 관리, `.bin`·`.lst` 생성 |

## 3. Parser와 심볼 테이블

Parser는 입력 줄을 `ParsedLine` 구조체로 변환한다. 구조체에는 라벨, mnemonic, operand 개수 및 operand 문자열이 저장된다. 공백 줄과 주석 줄, 라벨만 있는 줄도 구분해 처리한다. 메모리 참조 형태의 operand와 문자열 내부의 쉼표도 고려한다.

심볼 테이블은 동적 배열을 사용한다. 각 심볼은 이름, 주소, 유형, 전역 여부, 정의 여부를 가진다. 코드·데이터·BSS 라벨은 각각 `T`, `D`, `B` 유형으로 관리하고, 절대값 심볼은 `A`, 미정의 전역 심볼은 `U`로 표시한다. `.global` 및 `.globl` 선언과 실제 심볼 정의를 연결한다.

## 4. Pass 1: 크기 계산과 주소 배치

Pass 1은 소스 파일을 여러 차례 읽어 메모리 배치와 심볼 정보를 정한다.

- 기본 text 시작 주소는 `0x00010000`이다.
- 명령어와 의사 명령어의 크기를 반영해 text 크기를 계산한다.
- data 시작 주소는 text 끝 주소를 16바이트 경계로 올림 정렬해 계산한다.
- data 지시어의 크기를 계산한다.
- BSS는 data 뒤에서 시작하며 BSS 내부의 `.space`, `.align` 크기를 계산한다.
- 각 섹션의 라벨을 해당 주소와 함께 심볼 테이블에 등록한다.
- `.equ`와 전역 심볼 선언을 처리한다.

현재 구현에서 BSS 시작 주소 자체를 별도로 16바이트 정렬하지는 않는다. BSS 안에서 정렬이 필요하면 `.align`을 사용한다. `.bss`에서는 `.space`와 `.align`만 지원하며 다른 데이터 지시어는 오류다.

## 5. Pass 2: 기계어 인코딩과 데이터 출력

Pass 2는 Pass 1에서 계산한 주소와 심볼 테이블을 사용한다.

- 지원 명령어를 R, I, S, B, U, J, CSR, System 인코더로 전달한다.
- 라벨을 참조하는 분기 및 점프 명령어의 주소 차이를 인코딩에 사용한다.
- 구현된 의사 명령어는 실제 명령어 인코딩으로 확장한다.
- `.data`의 `.byte`, `.half`, `.word`, `.ascii`, `.asciz`, `.space`, `.align` 결과를 바이트 배열에 기록한다.
- 정렬로 생긴 출력 영역도 바이너리 배치에 반영한다.
- `.bss`는 초기화 데이터가 없으므로 `.bin` 바이트에 포함하지 않는다.

바이너리는 raw binary이며 ELF 헤더나 relocation 정보를 포함하지 않는다.

## 6. Listing 파일

`.lst` 파일에는 출력 항목별 주소, 기계어 또는 데이터 값, 대응하는 원본 소스 줄이 기록된다. 마지막에는 심볼 테이블이 출력되며 심볼 유형과 전역 여부도 확인할 수 있다. BSS 라벨은 심볼 테이블에서 확인한다.

## 7. 오류 처리

현재 확인한 오류 처리 사례는 다음과 같다.

- 알 수 없거나 유효하지 않은 명령어
- 중복 또는 유효하지 않은 라벨
- 존재하지 않는 심볼을 참조하는 명령어
- 잘못된 레지스터 이름
- 인코딩 범위를 벗어난 즉시값
- BSS에서 지원하지 않는 지시어

명령어 인코딩 관련 오류 메시지는 현재 mnemonic 중심으로 출력된다. 모든 오류에 대해 구체적인 원인(예: 잘못된 레지스터 이름 또는 즉시값 범위)을 개별적으로 설명하는 상세 진단 메시지까지 구현된 것은 아니다.
